## 구현

- 안내 시작 전에 “지금 이 아파트·동·호수에 있습니다” 체크 필수. 저장된 주소를 자동으로 현재 위치로 확정하지 않는다. 주소 입력이나 검색 결과 선택 후 체크를 해제한다. 위치를 모르는 경우 기존 건너뛰기는 유지한다.
- 결과 화면의 세부 위치·본인 포함 인원·이동 도움 필요 여부를 화면 상태에 보관한다. 상황 변경, 위치·답변 수정 후 다시 결과로 돌아와도 유지한다. 인원은 미확인 또는 1~999 정수만 저장 가능하다.
- `hasVulnerable: true / false / null`을 `submitReport`에 전달한다. 각각 이동 도움 필요 / 불필요 / 미확인이다. 기본값은 미확인이다. 판정 입력에는 추가하지 않았다.
- 마지막 성공 저장 시각·당시 주소·세부 위치·인원·지원정보·안내 결과를 화면 아래에 계속 표시한다. 실패 시 기존 성공 요약을 덮어쓰지 않는다. 이 브라우저 localStorage에 요약을 남겨 새로고침 후에도 표시한다. 과거 저장 내용임을 명시하며 실제 119 접수·전송으로 표현하지 않는다.
- 디자인 미리보기에서는 상태 저장 불가를 유지하고, 예시 입력이 실제 입력 상태를 덮어쓰지 않도록 했다.

## 질문·판정 통합 검토 (수정하지 않음)

이전 리뷰에서 “복도·계단 질문 삭제 합의와 불일치”라고만 설명했지만, 현재 공통 data.js는 뒤쪽에서 q4를 다시 정의한다. 현재 실행 코드 기준으로 비교해야 한다.

- 공통 q2는 `많음또는화염` 하나, 디자인 q2는 `많음`/`화염` 별도. 디자인은 판정 직전에 합치지만 저장되는 answers는 원본 값이다. 공통 화면에서 저장 답변을 재판정할 때 정규화 계약이 필요하다.
- 디자인 q3에 `막힘`이 추가되어 있고 공통 QUESTIONS에는 없다. 공통 판정은 해당 값을 명시 분기하지 않고 시설 대안으로 흐른다. 선택지·저장 스키마를 통합 검토할 것.
- 현재 공통 q4에는 `옥상안전`이 있고 q5(화점층과의 관계)를 사용한다. 디자인에는 옥상 선택지와 q5가 없고 결과 콘텐츠는 A~F뿐이다. 단순히 공통 질문을 복사하면 G 결과가 F 문구로 표시될 수 있으므로 질문/분기/결과를 함께 결정해야 한다.
- 공통 q3 설명과 디자인 q3의 위험한 확인 행동 관련 문구가 다르다. 공식 안내 검토 및 메인 판단 후 단일 정의로 통일할 것. 이번 작업에서는 화재 판정 규칙·선택지·행동 문구를 바꾸지 않았다.

## 통합 계약과 남은 범위

- 기존 store가 이미 `hasVulnerable` 3상태를 저장한다. 새 공통 저장소 필드는 불필요하다. 다른 역할 화면에서 null을 false로 표시하지 않는지 통합 확인 필요.
- 기존 `applyReport`의 세대 반영에는 `currentPlace`가 포함되지 않는 것으로 확인했다. 입주민 report에는 저장되므로 다른 역할이 세대 객체에서 현재 위치를 읽는다면 공통 저장소의 반영 계약을 메인에서 점검할 것.
- 미저장 세부정보는 같은 화면 세션의 이동에서 유지한다. 새로고침 후에는 마지막 저장 **요약만** 복원하고 세부 입력을 자동 재사용하지 않는다. 재진입 시 인원·위치가 바뀌었을 수 있기 때문이다.
- 저장 요약은 로컬 보조 기록이며 서버 수신증이 아니다. 요약용 localStorage 쓰기 실패 시 현재 화면의 요약은 보이지만 새로고침 복원은 보장하지 않는다.
- 사건 링크 연결, 서버 접수 확인, 다른 기기 동기화는 기존대로 지원하지 않는다.
- 디자인 담당 참고: 새 ID `confirm-location`, `resident-help`, `resident-last-saved`; 기존 `field`, `save-note`, `button` 클래스를 재사용했다. checkbox와 select의 모바일 레이아웃을 CSS 통합 시 확인할 것.
