# 119상황실 검토 및 반영

2026-11-05. 앱 경로: `/Users/macmoning/Documents/ChatGPT/세이프홈`. 배포·push 없음.

## 반영

- 기본 화면 상단에 전체 진행 사건의 긴급 미확인 메시지 건수·최장 경과시간, 부재·재연락 건수를 항상 표시. 경과시간은 1초마다 해당 텍스트만 갱신하여 입력 폼을 재생성하지 않는다.
- 선택 세대의 입주민 신고 시각·원문 상태와 최근 판단 출처·시각·근거를 분리. 전체 브라우저 저장 시각은 그 범위를 명시.
- `fieldObservation.source`를 우선 사용하고 이전 기록은 team 값으로 호환. 출처 식별 불가 기록은 미확인 표시. 상황실 기록의 활동 이력도 상황실 판단으로 표시.
- 최신 통화가 부재 또는 재연락이면 후속 업무에 남김. 같은 사건·세대에 연결 통화를 기록하면 해제. 긴급 미확인 메시지를 미처리 목록 상단에 정렬.
- 안전 변경은 잔류 0명 재확인과 최대 200자 확인 방법·근거 필수. 기존 우클릭/상태변경 버튼 유지.
- 사건 이동 취소 전에 검색 기록이 초기화되던 순서를 수정. 사건/미확정 탭 전환에도 작성중 메시지·검색 기록 확인 적용. 우클릭 시 이동 취소하면 다른 세대 상태 메뉴를 열지 않는다.
- 새 저장 수신 중 메시지 본문·수신대상·통화 입력 보존. 안전 근거 작성 중 메뉴도 유지하며 기존 revision 충돌 검증은 유지한다.

## 공통 저장소 계약

메인이 제공한 `updateFieldObservation({source:'situation', verificationMethod, ...})`에 연결했다. source/verificationMethod의 로그 보존과 `safe`에서 `remaining===0` 검증은 공통 저장소 책임이다. 공통 파일은 이 역할에서 수정하지 않았다.

## 검증

`tests/situation-desk.test.cjs`는 실제 Chromium에서 샘플 생성 → 긴급 메시지/부재 통화 → 후속 통화 해제 → 메시지/통화 작성 중 저장 수신 → 사건 이동 취소 → 안전 근거 누락 거절 → 근거 입력 및 안전 저장을 검증한다. 입주민 원문 danger 유지, 잔류 0명, 브라우저 오류 없음도 확인한다.

실행: Playwright가 설치된 환경에서 `NODE_PATH=<playwright 상위 node_modules> node --test tests/situation-desk.test.cjs`. Playwright 미설치 환경에서는 이 브라우저 테스트만 skip한다. 이번 환경에서는 skip 없이 통과했다.

## 남은 범위

- 선택 세대에는 가장 최근 판단이 표시된다. 과거 현장 확인과 상황실 판단 전체 흐름은 사건 활동 이력에서 확인한다.
- 안전 근거는 UI 필수이며 모든 호출 경로에 대한 공통 저장소 필수 정책은 메인 통합 판단 대상이다.
- 동시 변경으로 revision 충돌 시 근거를 보존하지만 최신 정보를 확인한 후 상태 메뉴를 다시 열어 저장해야 한다.
- 푸시 수신, 실제 119 연계, 기기 간 동기화, 서버 인증은 구현하지 않는다. 팀 이름 기반 이전 데이터 출처 추론은 인증된 역할 증명이 아니다.
- 전체 사건 알림의 업무 보기 버튼은 현재 선택 사건의 업무 영역을 연다. 다른 사건의 업무는 왼쪽 사건 목록에서 선택한다.
