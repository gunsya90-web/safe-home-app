## 반영

- 모바일(800px 이하) 119 전화 버튼을 하단 고정, 최소 높이 56px. safe-area 하단 여백, 본문 끝 여백, 토스트 위치 및 포커스 스크롤 여백을 확보했다. 전화 링크의 동작이나 실제119 연계 범위는 변경하지 않았다.
- 모바일의 장식용 건물 그림과 중복 내부 헤더를 생략하고 여백을 줄여 위치 확인·안내 시작과 위치 모름 선택을 앞당겼다. 기존 네이비/코랄 디자인 유지.
- 본문·입력·핵심 버튼 글자 최소 16px, 주요 보조 설명·데모 및 저장 안내 최소 14px. 낮은 대비의 안내문과 placeholder를 진하게 조정했다. 대기 결과 카드 배경도 흰 글자 대비를 높였다.
- 위치 모름 선택을 48px 높이의 명확한 보조 버튼으로 변경. 위치·답변 수정 및 이전 버튼은 최소 44px 터치 영역, 보조 행동 버튼은 48px 확보.
- 모바일 결과의 상황 변경·음성 버튼을 한 열로 배치하고, 태블릿(1000px 이하)은 소개 열을 숨긴 단일 앱 열로 배치했다.
- 입주민 역할의 동시 변경으로 추가된 위치 확인 checkbox가 기존 text input 공통 규칙의 width 100%/height 54px를 받는 것을 발견, checkbox 전용 22px 크기와 44px label 영역으로 수정했다.

## 실제 브라우저 검증

전용 CUA 도구 대신 로컬 Playwright + 설치된 Google Chrome(headless)로 실행·스크린샷을 확인했다. 정적 소스 확인만 수행한 것은 아니다.

- 화면 크기: 375×667, 390×844, 768×1024, 820×1180, 1440×1000, 추가 320×568.
- 위치 화면 → 위치 모름 → 우리 집 → 현관 상태 모름 → 결과 흐름 실행.
- 모든 크기의 시작/질문/결과에서 가로 넘침 없음. 모바일 119 버튼은 각 단계 및 결과 끝 스크롤에서도 화면 내에 있고 중심점 hit-test 성공.
- 375×667 최초 화면 실측: 안내 시작 y=461.4~515.4, 위치 모름 y=525.4~573.4, 119 전화 y=599~655. 세 버튼 모두 최초 화면에 온전히 표시되고 중심점 hit-test 성공.
- 수정 버튼 44px, 위치 모름 48px, 전화 56px. 375px 화면의 본문 크기 20px에서도 가로 넘침과 전화 가림 없음.
- 820×1180 태블릿 단일 열 화면 시각 확인. 런타임 pageerror는 앞선 6종 크기 검증에서 0개.
- 실제 전화는 걸지 않았고, 테스트 브라우저는 별도 임시 프로필을 사용했다.

## 통합 계약 및 미해결

1. `.phone-button`은 현재 `#screen` 아래 각 화면에 하나다. 이를 유지하면 모바일 고정 규칙이 적용된다. 모바일에서는 `.screen-content` 애니메이션을 끈다. transform을 가진 조상이 fixed 위치를 바꿀 수 있으므로 후속 변경에서 app-shell/workspace에 transform/filter를 추가하지 말 것.
2. 화면 끝 본문은 body 하단 여백으로 전화 위까지 스크롤할 수 있다. 아주 작은 320×568 화면 및 큰 글자/검색결과/오류 메시지 표시 시 시작 버튼까지 스크롤이 필요할 수 있다. 폰트와 버튼 크기를 줄여 강제로 한 화면에 넣지 않았다.
3. iOS Safari/Android 실기기, 소프트 키보드 열림, OS 글자 확대 및 스크린리더는 미검증. 모바일 키보드가 열린 상태의 fixed CTA 동작은 실기기 통합 QA 필요.
4. 디자인 설정을 사용자 화면에서 분리하거나 질문 단계 표시를 동적 진행에 맞추는 일은 마크업/JS 담당 범위. 본 CSS 작업에서는 의미나 판정·저장 동작을 바꾸지 않았다.
5. 기존 DOM에서 전화 링크 다음에 위치 모름 버튼이 오지만 시각적으로 전화는 하단 고정된다. 후속 접근성 통합에서 공통 전화 영역을 main 다음에 두는 마크업을 고려할 수 있다. 현재 키보드 포커스 outline과 scroll-margin은 유지한다.
6. 공통 store/rules/data 변경 요청 없음. 최종 통합 후 입주민 역할의 최종 마크업과 위 실측 조건을 다시 확인할 것.
