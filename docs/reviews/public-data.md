## 기존 앱과의 연결 계약

1. 현재 `data-review.html`/`js/kapt-review.js`는 K-apt 수집 JSON만 읽는다. 신규 GeoJSON이나 부동산원 JSON을 그대로 넣으면 안 된다. 별도 유형 검증·미리보기 어댑터가 필요하다.
2. 진입점은 `sourceId + kaptCode + entranceNumber`로 식별하고 WGS84 `[longitude, latitude]`만 사용한다. 원본 `좌표x/y`의 CRS를 추정하지 않는다. `sourceDate`, `retrievedAt`, `verificationStatus`, 원문 메모를 유지한다.
3. 단지(K-apt)→동(대장PK·주소 건물관리번호·GIS ID)의 명시적 연결표에 `matchMethod`, `evidence`, `reviewedAt`, `reviewer`를 저장한다. 주소+이름 유사 일치는 후보이며 자동 확정하지 않는다. 부동산원 ID는 문자열로 보존하고 조인에서만 trim한다.
4. 비정형 건물은 `floors[]`마다 `floorId`, `floorLabel`, `units[]`를 갖고 실제 호명칭을 보존한다. 20~49층·층당 6~8호가 서로 달라도 표현한다. 최고층·총세대수만 있는 공공자료로 생성하지 않는다. 상가·피난층·복층을 별도 구분한다.
5. 세대 시설의 기존 `true/false/null`, source, verifiedAt, inspector 계약을 유지한다. 단지자료의 범위는 `complex`로 남기고 검증된 동·층·호 범위를 지정하기 전까지 `setUnitFacility`를 호출하지 않는다.
6. 수집 변경분 검토→명시적 범위 확인→앱 반영 상태 기록 순서를 따른다. 기존 현장확인과 진행 사건 스냅샷을 덮어쓰지 않는다. 신청·승인·수신·검증·반영은 별도 상태다.
7. 네이버 Maps는 요청 시 지도 표시·경로 조회에 사용한다. 결과 좌표·타일·경로의 영구 DB화/재사용은 공식 약관 제한 때문에 수집 대상에서 제외한다. 현재 네이버 연동은 구현·검증하지 않았다.
