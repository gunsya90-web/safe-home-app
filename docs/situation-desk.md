# 상황실 화면

접속: `/situation.html`. 기존 역할 앱(`/`)과 별도인 상황실 디자인 데모입니다.

## 구성

- 왼쪽: 진행 사건·미확정 신고. 등록 건물의 선택 신고를 데모 사건으로 연결 가능.
- 중앙: 사건 집계, 층·상태 필터가 있는 세대 현황, 활동·메시지·통화 이력.
- 오른쪽: 선택 세대의 입주민 원문/현장 확인, 메시지 작성, 미처리 업무.
- 샘플 열기: 별도 `[샘플] 상황실 아파트` 30층 8세대/층, 240세대. 입주민 샘플 신고 5건. 기존 사건이나 신고를 초기화하지 않음.

## 메시지 흐름

1. 상황실 상단에 담당자 이름 입력.
2. 진행 사건과 호수(또는 사건 전체)를 선택하고 수신 대상·우선순위·내용 입력.
3. 앱에 저장. `현장 미확인` 상태가 미처리 업무에 표시됨.
4. `/field.html`에서 같은 진행 사건 선택, 수정자 이름·팀 설정.
5. 상단 메시지함에서 `확인 → 조치 시작 → 완료`. 동일 수신 대상 또는 현장 전체 메시지에만 응답 가능.
6. 상황실의 상태·이력·미처리 업무가 갱신됨.

대상 이름·팀은 자기 입력 데모 값이며 서버 권한 검증이 아닙니다. 브라우저 저장과 실제 대원 확인을 구분합니다. 전달 성공·푸시 수신을 추정하지 않습니다. 메시지는 사건 범위이며 사건 종료 후 추가 발신/응답을 거절합니다. 메시지 정정·첨부·직접 채팅·푸시는 아직 구현하지 않았습니다.

## 통화 기록

세대를 선택해 통화 기록을 엽니다. 연락처 직접 입력 시 `tel:` 전화 링크가 나타납니다. 실제 전화 연결은 기기 기능에 따릅니다. 연결·부재·재연락 필요와 확인 내용을 수동 기록합니다. 실제 통화 여부나 녹음을 자동 검증하지 않습니다. 같은 사건·세대의 최신 통화가 재연락 필요이면 업무함에 남으며 다음 연결 기록을 남기면 해제됩니다.

## 보존 및 한계

메시지·응답 이력·통화 기록은 기존 v5 저장소와 관리자 백업에 포함됩니다. 수정자·시간과 사건별 활동 로그를 남깁니다. 다른 기기와 자동 공유하지 않으며 같은 출처·브라우저 프로필의 탭에서만 연동됩니다. 새 기능 반영을 위해 기존 현장대원 탭은 새로고침해야 합니다.

편집: `situation.html`, `css/situation-desk.css`, `js/situation-desk.js`, `js/field-messages.js`, `js/store.js`.

## 간소화 화면과 세대 상태 변경

기본 화면은 사건 목록·작전도·선택 세대 상세로 구성합니다. 상단 `메시지·기록` 버튼으로 부가 업무를 펼칩니다. 세대를 클릭하면 세부정보, 우클릭하면 상태 메뉴가 열립니다. 터치·키보드에서는 상세의 `상태 변경` 버튼으로 같은 메뉴를 엽니다. 구조 필요/구조 중/대기/이동/안전/미응답을 변경할 수 있으며 안전은 잔류 0명 확인을 한 번 더 요구합니다. 입력한 상황실 담당자와 변경 전후 값은 기존 현장 확인 로그에 남습니다. 입주민 원문은 보존하며, 구조 중은 현장대원 화면과 공유되는 `rescuing` 상태입니다.
