# SAFE-HOME

입주민·상황실·현장대원·관리자·시설 점검의 화재 대응 흐름을 검토하는 정적 웹앱 데모입니다.

**실제 119 접수 시스템이 아닙니다.** 저장·동기화는 같은 출처의 같은 브라우저에서만 동작합니다. 관리자 비밀번호와 점검 링크는 데모용이며 서버 인증을 제공하지 않습니다.

## 실행·검증

Node.js 22 이상에서 외부 패키지 설치 없이 실행합니다.

```sh
npm run dev
npm test
```

앱 주소: http://127.0.0.1:4173

역할은 입주민(기본), `?role=situation`, `?role=admin`입니다. 관리자 데모 비밀번호는 `01190119`이며, 현장대원·입주민 사건 링크와 시설 점검 링크는 관리자 화면에서 발급합니다.

## 검토 반영

기준 저장소는 `gunsya90-web/safe-home-app`, 기준 커밋은 `f87fc00a78e21a2841f9b826a3cb9de1b8cbc083`입니다. 다른 프로젝트 자료는 구현 근거로 합치지 않았습니다.

- 사건·건물·세대별로 신고를 분리하고 관리자가 선택한 미확정 신고만 연결합니다.
- 종료·만료·대상 불일치 링크를 차단하고 현장 상태와 새 신고의 충돌을 표시합니다.
- 사건 생성 시 시설정보를 보관해 화면별 판단 기준을 맞춥니다.
- 경로 확인 질문을 복원하고, 모르는 시설·인원은 미확인으로 표시합니다.
- 저장 실패를 알리고 기존 데이터 보존, 백업 다운로드·복구, 종료 기록을 지원합니다.
- 입력·상태·안내 디자인, 키보드 포커스, 확대 허용, 작은 화면 배치를 보완했습니다.

자세한 결과는 [반영 및 디자인 검토](docs/implementation-review.md), 현재 흐름은 [업무 흐름도](docs/workflow-v5.md)를 참고하세요. 기존 검토 문서는 작성 당시의 기록이며 현재 동작은 이 문서와 코드를 기준으로 합니다.

## 건물 가져오기

CSV/TSV 열은 `apt,dong,ho,complexCode,address`입니다. 단지코드 또는 주소 중 하나가 필요합니다. 같은 이름의 단지를 합치지 않도록 식별자를 사용합니다. 인용부호 안 쉼표·줄바꿈을 지원합니다.

## 데이터·배포

v4 데이터는 원본을 보존하고 과거 신고·사건을 보관 상태로 이관합니다. 손상된 저장 데이터는 자동 초기화하지 않습니다. 초기화·복구 전 관리자 화면에서 백업하세요. 브라우저 저장소는 서버 데이터베이스의 동시성·복구 보장을 제공하지 않습니다.

GitHub Actions는 테스트 후 공개 앱 파일만 `dist`에 모아 Pages로 배포합니다. 이번 검토에서는 GitHub push·배포를 실행하지 않았습니다. 실행 중인 기존 사건에는 나중에 수정한 건물 시설정보가 자동 적용되지 않습니다.

실운영 전에는 서버 인증·권한, 기기 간 동기화, 링크 검증, 개인정보 보관 정책, 대피 규칙·시설 사용 안내의 소방 전문가 검증이 필요합니다.
